## 觀察

1. **指令理解正確、安全機制有效**：協調 Agent 在模型有回應時的合法率 97.5%（第四步 480 次），各機 Agent 96.6%；不合法的輸出全部被白名單驗證擋下、沒有送出。懸停 / 返航期間 Agent 自行改計畫 0 次。最小 3D 機間距離都 ≥ 5 m（返航多 Agent 有一次 5.4 m：返航不做 C 端去衝突，靠高度層分開 5 m，A 的安全層最後把關）。
2. **LLM 比規則式慢**：每次決策 1.5–3 s（規則式 < 0.1 s），下令包圍要 36–44 s（規則式 25 s）、中途改口抓拍下令後 31–55 s（規則式 17 s）。規則式是針對這個幾何問題手調的，LLM 的價值在聽懂各種說法的自然語言、在做不到時說明原因（例如「降落在屋頂」→ 懸停並說明沒有這個功能），不是比規則式快。
3. **抓拍變慢的原因（看 events.jsonl 找到）**：LLM 不知道捕捉區在哪裡，角色固定照編號分（uav1 驅趕、uav3 抓拍），而且偏好派 overwatch（高空監看）而不是 blocker（封鎖）；規則式依「誰在目標後方、誰離捕捉區最近」分派。已在 `d40be5c` 之後的版本把捕捉區與各機相對位置（ahead_m、to_zone_m）放進給 LLM 的世界狀態，並在 prompt 說明怎麼依位置分派——**這版還需要再跑一次 LLM 驗證**。
4. **剩下的不合法輸出**：主要是目標暫時不在清單時沿用上一個計畫的 target_id（11 次），已被驗證擋下並重送或沿用上一個計畫。
5. **第五步（各機 Agent 也用 LLM）**：每分鐘約 30 次請求，免費額度不夠，約 30% 是 429、10% 是 503 / 504。這些都改用規則式頂上，所以結果混合了規則式；要正式評估各機 LLM 需要付費額度或把各機 Agent 的週期拉長。模型真正回應的部分，合法率 96.6%。
