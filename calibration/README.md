# 相機校正（Camera Calibration）

Phase 0 交付物：相機校正理論 + OpenCV demo。本資料夾的腳本 `calibrate.py` 用棋盤格影像估計相機內參 K 與畸變係數，並量化重投影誤差。

## 1. 為什麼需要校正

Phase 2 要把 bbox 的像素座標 `(u, v)` 轉成世界座標。第一步是把像素變成「相機座標系裡的一條射線」，這需要內參矩陣 K；若鏡頭有畸變，還要先去畸變，否則越靠近影像邊緣誤差越大。

## 2. 針孔相機模型

世界點 `P_w = (X, Y, Z)` 投影到像素 `(u, v)`：

```
s · [u, v, 1]ᵀ = K · [R | t] · [X, Y, Z, 1]ᵀ

K = | fx   0   cx |
    |  0  fy   cy |
    |  0   0    1 |
```

| 參數 | 意義 | 單位 |
|---|---|---|
| `fx, fy` | 焦距，以像素為單位（`f / 像素實際尺寸`） | px |
| `cx, cy` | 主點，光軸穿過影像平面的位置，通常接近影像中心 | px |
| `R, t` | 外參：世界座標系到相機座標系的旋轉與平移 | 無 / m |
| `s` | 尺度（深度），反投影時未知，需要額外條件求解 | m |

**重點**：單張影像只有 `(u, v)`，沒有深度 `s`，所以 pixel → world 需要額外假設（本專案是地面平面假設）。內參 K 是相機自己的屬性，外參是「相機在哪裡、朝哪裡」，每張影像都不同。

## 3. 鏡頭畸變

OpenCV 的畸變係數順序為 `(k1, k2, p1, p2, k3)`：

- 徑向畸變 `k1, k2, k3`：離主點越遠偏移越大。`k1 < 0` 為桶狀（直線向外凸），`k1 > 0` 為枕狀。
- 切向畸變 `p1, p2`：鏡頭與感光元件沒有完全平行造成，通常很小。

設正規化座標 `(x, y)`，`r² = x² + y²`：

```
x_d = x(1 + k1·r² + k2·r⁴ + k3·r⁶) + 2·p1·x·y + p2·(r² + 2x²)
y_d = y(1 + k1·r² + k2·r⁴ + k3·r⁶) + p1·(r² + 2y²) + 2·p2·x·y
```

## 4. 校正方法（Zhang's method）

1. 拍多張不同姿態的平面棋盤格，偵測角點（`findChessboardCorners`，再用 `cornerSubPix` 精修到亞像素）。
2. 每張影像可算出棋盤平面到影像的單應矩陣 H，H 對內參 K 提供兩個約束。
3. 多張影像疊加後線性求解 K 的初值，再用 Levenberg–Marquardt 非線性最佳化，同時調整 K、畸變係數與每張影像的外參，使「重投影誤差」最小。

**為什麼要有角度變化**：若每張都是正面平拍，H 提供的約束退化，K 的估計不穩定。這也是 `calibrate.py` 在影像少於 10 張時會警告的原因。

## 5. 重投影誤差

把已知的 3D 棋盤角點用估計出的 K、畸變、外參投影回影像，與偵測到的角點比較，距離平方的平均再開根號，即 RMS（單位 px）。

- 驗收標準：平均 < 0.5 px。
- **低重投影誤差不代表校正一定準**：它是用「參與校正的影像」算出來的訓練誤差，可能過擬合。`--experiment` 模式用沒參與校正的影像（holdout）評估，才反映泛化品質。
- 腳本會同時印出 `cv2.calibrateCamera` 回傳的整體 RMS 與各影像 RMS 的平均，兩者計算方式略有不同（前者是全部角點合併、後者是每張先算再平均），報告請寫清楚引用的是哪一個。

## 6. 與模擬環境的關係

Gazebo 的模擬相機通常沒有畸變，內參可由 SDF 的水平視角與解析度直接算：

```
fx = (W / 2) / tan(HFOV / 2),   fy = fx,   cx = W / 2,   cy = H / 2
```

`calibrate.py` 也會由校正出的 `fx` 反推 HFOV，方便與這個公式對照。真實鏡頭校正的價值是：(1) 理解 K 與畸變怎麼來；(2) 之後若要上真機，這套流程可直接沿用。

## 7. 使用方式

```powershell
pip install opencv-python numpy
# 影像放在 calibration/images/（已被 .gitignore 排除，不會進 repo）
python calibration/calibrate.py --cols 9 --rows 6 --square 0.025
python calibration/calibrate.py --cols 9 --rows 6 --square 0.025 --experiment
```

- `--cols`、`--rows` 是**內角點數**，不是方格數（10×7 方格 = 9×6 內角點）。
- `--square` 是方格邊長（公尺），只影響外參的平移量，**不影響 K 與畸變係數**。
- 輸出在 `calibration/output/`：`calibration_result.json`、`undistort_*.png`（前後對照）、`corners/`（角點偵測結果，用來檢查哪張偵測錯）。

## 9. 口試可能被追問

1. **K 的每個參數是什麼意思？** 見第 2 節；特別說明 fx 是像素單位的焦距。
2. **為什麼不能只用一張影像校正？** 單張的單應只提供 2 個約束，不足以解出所有內參，且容易過擬合。
3. **重投影誤差低就代表校正準嗎？** 不一定，見第 5 節，要用 holdout 影像驗證。
4. **模擬環境還需要校正嗎？** 通常不需要，內參由 HFOV 與解析度直接算；但仍須確認 SDF 沒有設畸變。
5. **校正結果對 pixel → world 的影響有多大？** 內參誤差、畸變殘餘都會讓射線方向偏移，高度越高、離影像中心越遠影響越大。這是 Phase 2 誤差量化的一個誤差源。

## 10. 值得鑽研

- **ChArUco / AprilTag 標定板**：比純棋盤格穩健，棋盤可被部分遮擋或位於邊緣也能使用，是業界較常用的做法。
- **魚眼鏡頭**：OpenCV 有獨立的 `cv2.fisheye` 模型，一般畸變模型在大視角下會失效。
- **相機與 IMU 的聯合校正**：真機上，相機相對機體的外參（本專案的 `R_bc`）也需要校正，業界常用 Kalibr。
- **標定板品質**：平整度與印刷尺寸誤差會直接進入 K，這也是重投影誤差之外的系統誤差來源。
